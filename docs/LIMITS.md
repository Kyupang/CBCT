# LIMITS — 지원하지 않는 것 / 검증하지 않은 것

> **이 프로젝트는 학습용 데모다. 의료기기가 아니며 진단·치료·임상 판단에 사용할 수 없다.**
> 임상 검증, 소프트웨어 수명주기(IEC 62304), 위험관리(ISO 14971), 인허가(MFDS/FDA) 어느 것도 거치지 않았다.

## 입력 형식

- 전송 구문은 **Implicit VR LE, Explicit VR LE만** 지원한다.
  - JPEG / JPEG-LS / JPEG2000 / RLE / Deflate / Explicit Big Endian은 파일 단위로 제외되고 이유가 표시된다.
  - 실제 CBCT 장비 출력은 압축인 경우가 많아서 그대로는 못 읽을 수 있다.
- 단일 프레임 grayscale만 지원한다. Multi-frame(Enhanced CT/MR, 많은 CBCT 출력 형식), 컬러, Palette는 지원하지 않는다.
- BitsAllocated 8/16만 지원한다. 32bit, float pixel data는 지원하지 않는다.
- MONOCHROME1(반전 표시)을 반전하지 않는다. CT/CBCT는 대개 MONOCHROME2다.
- DICOMDIR을 해석하지 않는다(파일은 무시하고 이미지 파일만 읽는다). 시리즈가 여러 개면 `ImageType`으로 원본 볼륨을 골라 하나만 보여 준다(재구성·위치 확인 영상은 제외, DENTAL-LOG D2). 사용자가 시리즈를 고르는 UI는 없다.
- 오버레이 평면(60xx)과 픽셀에 새겨진 글자는 표시도 제거도 하지 않는다.
- Modality LUT 시퀀스, VOI LUT 시퀀스, Presentation State는 지원하지 않는다. 선형 slope/intercept와 선형 W/L만 쓴다.
- 압축 해제 없이 전체를 메모리에 올린다. 매우 큰 시리즈(>~1 GB)는 브라우저 메모리 한계에 걸릴 수 있다.

## 기하

- **Gantry tilt / 전단(sheared) 스택은 보정하지 않는다.** IPP가 법선에서 0.5 mm 넘게 벗어나면 경고만 띄우고, 직육면체 격자로 취급한다.
- 시리즈 안에서 IOP가 다르거나(1e-3 초과) 크기·PixelSpacing이 다른 슬라이스는 제외한다.
- 슬라이스 간격
  - 균일 판정 기준은 잔차 2%다.
  - 빠진 슬라이스는 **선형 보간으로 채운다**. 채워진 슬라이스는 실제 측정값이 아니다(UI에 경고 표시).
  - 간격의 10배를 넘는 gap은 가장 긴 연속 구간만 사용한다.
- MPR은 **획득 격자 기준 직교 평면**이다. oblique 획득이면 화면의 axial/coronal/sagittal은 진짜 해부학 평면이 아니다(방향 글자로 표시). 임의 각도 reslice UI는 없다. 치과 파노라마/cross-section은 있다(아래).
- MPR은 nearest-neighbor 슬라이스다("화면 보간" 옵션은 화면 확대 보간일 뿐이다). 커서 값은 가장 가까운 복셀 값이다.
- 거리 측정
  - 같은 평면 안 두 점 사이의 직선 거리(mm)만 잰다.
  - 정확도는 복셀 크기와 클릭 위치에 좌우되고, 서브픽셀 엣지 검출은 없다.
  - 측정 결과는 저장하지 않는다(새로고침하면 사라짐).
  - 각도, 면적, HU 통계 ROI는 없다.
- PixelSpacing이 없으면 1 mm로 가정한다(경고). ImagerPixelSpacing, 보정 정보, CBCT 장비별 보정은 고려하지 않는다.

## 치과 모드 (파노라마 / cross-section)

- 치열궁은 **획득 격자의 축상면 한 장** 위의 곡선이다. 환자 머리가 기울어 찍혔으면(P221은 약 24°) 교합평면에 맞춰 볼륨을 돌리는 기능은 없다.
- 자동 치열궁 추정은 포물선 하나(RANSAC)라서 하악지 쪽 곡선을 못 따라간다. 장비 SW 파노라마 206 mm 대비 137 mm였다(DENTAL-LOG D7). 직접 찍은 점은 옮기거나 지울 수 없고 다시 찍어야 한다.
- 파노라마는 두께 방향 단순 평균이다. 장비 SW처럼 얇은 층을 깊이별로 만들거나, 초점층 모양을 바꾸는 기능은 없다.
- 파노라마·단면 위 거리 측정, 신경관 표시, 임플란트 배치, 치아 번호(FDI)는 없다.
- 장비 SW가 내보낸 재구성 영상의 헤더 좌표는 원본 볼륨과 수 mm~1 cm 어긋날 수 있다(관찰 2건, DENTAL-LOG D4). 이 뷰어는 그 영상들을 볼륨에 겹쳐 쓰지 않는다.

## 3D

- MIP와 단일 임계값 ISO 표면만 있다. 다중 구간 transfer function, 그림자, 클리핑 평면, 세그멘테이션, 메시 추출(STL)은 없다.
- 3D 텍스처는 R16F(|HU| ≤ 2048 정확, 그 위는 2 HU 단위)이고, 64M 복셀을 넘으면 다운샘플된다. 3D 표시는 측정용이 아니다.
- 실제 GPU에서의 프레임레이트·메모리는 측정하지 않았다(스크린샷은 headless 소프트웨어 렌더러).

## 데이터·검증 범위

- 자동 테스트는 합성 팬텀, 공개 샘플(축소 CT 2세트, MR 1세트), **실제 치과 CBCT 2건**(ToothFairy, NewTom VGi 1개 기종)으로 했다. 다른 제조사(Vatech, Planmeca, 덴티움 등)의 CBCT 출력은 확인하지 않았다.
- 다른 구현과의 교차 검증: pydicom(팬텀), ITK/SimpleITK(실제 CBCT 2건, 400점씩 값 일치). 3D Slicer GUI에서 직접 점을 찍어 비교하지는 않았다. 제조사 데스크톱 뷰어와는 그 장비가 내보낸 재구성 영상으로만 간접 비교했다.
- 접근성, 다국어, 모바일 터치, 브라우저 호환성(Chrome 외)은 확인하지 않았다.

## 클라우드 (cloud/)

- 로컬 데모다. S3는 SeaweedFS, DB는 SQLite, 완료 처리는 API 요청 안에서 동기로 돈다(P221 약 3초). 실제 운영이라면 큐(SQS) + 별도 작업자, PostgreSQL(RDS), CloudFront가 필요하다.
- 업로드는 파일 단위다. 수백 MB짜리 단일 파일(멀티프레임 CBCT)을 위한 S3 multipart 업로드는 구현하지 않았다.
- 압축 전송 구문(JPEG 2000 등) DICOM은 서버 변환에서도 읽지 못한다(뷰어와 같은 로더).
- 원본 DICOM은 `raw/`에 그대로 보관한다. 태그 익명화, 픽셀에 새겨진 글자 제거는 하지 않는다. 변환된 볼륨에는 태그를 복사하지 않는다.
- 인증: refresh token, 로그인 시도 제한, 비밀번호 재설정, 다중 인증, 병원 안 세부 권한은 없다. JWT 비밀키와 S3 키는 개발용 기본값이다.
- 장비 PC 쪽 데스크톱 뷰어 연동은 ITK 스크립트로 흉내 냈다. 실제 C++/Qt 클라이언트는 없다.
- 측정은 headless Chrome의 네트워크·CPU 에뮬레이션으로 했다(소프트웨어 WebGL). 실제 병원 회선과 내장 그래픽 PC에서는 재지 않았다.

## 보안·개인정보

- 모든 처리는 브라우저 로컬에서 하고 서버 업로드는 없다. 익명화 기능은 없다(환자 정보를 화면에 표시하지 않을 뿐).
- 공개 데이터셋에도 생년월일 등이 남아 있었다(DENTAL-LOG D6). 받은 원본과 거기서 만든 기준값 JSON은 git에 올리지 않는다.
- 개발 서버의 `/external` 경로는 개발용이다(`apply: 'serve'`). 빌드 산출물에는 포함되지 않는다.
